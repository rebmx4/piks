# Проверка первого быстрого свайпа в APIKS

Владелец подтвердил: в установленной сборке `1790690505` первый быстрый
горизонтальный свайп по пустому месту после ножниц, выделения или ромбика
может не двигать ленту. В Safari на том же iPhone проблема не воспроизводится.
Это локализует различие в среде приложения, но не доказывает причину внутри UIKit.

Исходная рабочая оболочка: `720ad82`, `D:/Projects/piks`. Новый вариант — ветка
`fix/native-input-20261007`, отдельная рабочая копия на D:. Существующее приложение
`com.piks.app`, Apple ID `6794464999`; проект, инструменты и веб-редактор остаются прежними.

Одна проверяемая гипотеза: отдельный жест скрытого меню трёх пальцев может
задерживать завершение касания. Ему явно выставлены `delaysTouchesBegan = false`
и `delaysTouchesEnded = false`; число пальцев, длительность и меню сохранены.
Это тестовый вариант, а не подтверждённое устранение пропуска.

В TestFlight/Debug добавлен `InputTraceRecognizer`: он не распознаёт жест,
не отменяет и не задерживает касания, не препятствует другим распознавателям.
Он пишет начало/конец/отмену UIKit, физические координаты, время, число движений,
сдвиг, задержку доставки и состояния меню/прокрутки. На каждом движении сообщений
и обращений к JavaScript нет. Предел — 60 начал в минуту с явной записью лимита.
Запись только на текущем URL `/ryn-next/`, в веб-редакторе приёмник фильтрует
видимый экран. Приёмник `window.__ryndiInputTrace` подготовлен в Ryndi на ветке
`fix/native-input-diagnostics-20261007`; старая оболочка его не вызывает.

Рекомендации Apple: [задержка завершения касания](https://developer.apple.com/documentation/uikit/uigesturerecognizer/delaystouchesended),
[подкласс распознавателя](https://developer.apple.com/documentation/uikit/implementing-a-custom-gesture-recognizer).

Проверено локально: синтаксический разбор двух Swift-файлов tree-sitter-swift 0.7.4;
приём и полная запись сообщения UIKit без перемещения/выделения/отмены в браузерном
сценарии Chrome и WebKit; две проверки передачи полного сообщения через logqueue.
Сценарий сначала падал: приёмника сообщения UIKit в исходном варианте нет.

На Windows нет Xcode. Компиляция iOS и поведение UIKit на iPhone пока не проверены.
Codemagic не запускался. Автозапуск workflow по push остаётся отключённым.
Перед тестом необходимы выкладка приёмника только в NEXT через deploy.py и одна
явно разрешённая владельцем сборка этой ветки в существующее приложение TestFlight.
Публикация в App Store и изменения `/ryn/` не входят в задачу.

После установки: ножницы → сразу свайп по пустому месту; затем то же после
ромбика и выделения. Если пропуск остался, сопоставить `stream: native` с pointer/touch
по координатам и времени. Запись UIKit без соответствующего потока страницы означает
потерю до JavaScript; наличие обоих потоков требует проверки состояния/отрисовки.
Отсутствие записи при превышении явно указанного лимита не доказывает потерю касания.
